初识agent

发表于2026-05-12|更新于2026-05-21|AI agent

什么是agent

agent被定义为通过传感器(Sensor)获取环境(Environment)信息，并自主地通过执行器(Actuators)采取行动(Action)来达成特定目标的实体。
LLM的出现让agent从过去的“按规则执行任务的程序”变为了更接近“能理解目标，分解任务，调用工具，持续修正”的智能系统。

AI agent相较传统agent有如下改变：

  1. 从规则驱动变成语言驱动
    传统 agent 往往依赖手写规则、状态机、固定流程。
    LLM 出现后，用户可以用自然语言给目标，agent 能理解意图、上下文和约束，再决定怎么行动。

  2. 具备通用推理与规划能力
    过去的 agent 通常只能处理特定任务。
    LLM 让 agent 能做任务拆解，比如“调研一个市场”可以被拆成搜索资料、比较信息、总结结论、生成报告等步骤。

  3. 工具调用成为核心能力
    LLM 本身只是“脑”，但 agent 可以接上浏览器、代码解释器、数据库、API、文件系统、办公软件等工具。
    这让 agent 不只是回答问题，而是能实际执行任务。

  4. 记忆和上下文管理变得重要
    LLM agent 可以保存用户偏好、历史任务、项目状态，形成短期或长期记忆。
    这让 agent 更像一个持续协作的助手，而不是一次性问答系统。

  5. 交互方式更自然
    用户不需要写复杂指令或配置流程，可以直接说“帮我分析这个项目”“修一下这个 bug”“整理成表格”。
    Agent 负责把自然语言目标转成具体操作。

  6. 多 agent 协作成为可能
    LLM 可以扮演不同角色，比如规划者、执行者、审查者、研究员、代码工程师。多个 agent 可以分工合作，处理更复杂的问题。

  7. 从自动化走向半自主工作流
    传统自动化是“我告诉程序每一步怎么做”。
    LLM agent 是“我告诉它目标，它自己决定步骤，并在必要时向我确认”。

agent的构成和运行原理

任务环境定义

在AI领域，通常使用PEAS模型来描述一个任务环境，即分析其性能度量(Performance)、环境(Environment)、执行器(Actuators)和传感器(Sensors) 。

agent的运行机制

下图展示了agent于环境之间的循环交互流程

该循环包括如下几个阶段：

  1. 感知(Percption): agent通过传感器（例如，API 的监听端口、用户输入接口）接受环境的输入信息，这些输入信息既可以是用户提出的自然语言形式的要求，也可以是上一步行动导致环境变化的反馈。

  2. 思考(Thought)：感知到信息后，agent进入决策阶段。对于LLM agent，这通常是由大语言模型驱动的内部推理过程。如图所示，“思考”阶段可进一步细分为两个关键环节：

  • 规划(Planning)：agent通过当前观察及内部记忆，更新对任务和环境的理解，并制定或调整一个行动计划，这个行动计划可能由多个子计划组成。
  • 工具选择(Tool Selection)：根据当前计划，agent从其工具库中选择合适的工具，确定调用工具的参数来执行计划。
  1. 行动(Action)：决策完成后，智能体通过其执行器执行具体的行动。这通常表现为调用一个选定的工具（如代码解释器、搜索引擎 API），从而对环境施加影响，意图改变环境的状态。

agent会不断重复上述流程，直到达到目标状态。

agent的感知与行动

在工程实践中，为了让 LLM 能够有效驱动这个循环，我们需要一套明确的交互协议 (Interaction Protocol) 来规范其与环境之间的信息交换。

在许多现代agent框架中，这一协议体现在对agent每一次输出的结构化定义上。agent的输出不再是单一的自然语言回复，而是一段遵循特定格式的文本，其中明确地展示了其内部的推理过程与最终决策。
这个结构通常包含两个核心部分：

  • Thought (思考)：这体现agent思考决策的流程。它以自然语言形式阐述了agent如何分析当前情境、回顾上一步的观察结果、进行自我反思与问题分解，并最终规划出下一步的具体行动。
  • Action (行动)：这是agent基于思考后，决定对环境施加的具体操作，通常以函数调用的形式表示。

例如，一个用于规划路线的agent可能会产生如下格式化输出：

Thought:用户想要得知从A地点到B地点的最短路线，我需要调用路线查询工具。  
Action：get_route(A,B)

这里的Action字段构成了对外部世界的指令。一个外部的解析器 (Parser) 会捕捉到这个指令，并调用相应的get_route函数。

行动执行后，环境会返回一个结果。例如，get_route函数可能返回一个包含详细路线规划的 JSON 对象。然而，原始的机器可读数据（如 JSON）通常包含 LLM 无需关注的冗余信息，且格式不符合其自然语言处理的习惯。

因此，感知系统的一个重要职责就是扮演传感器的角色：将这个原始输出处理并封装成一段简洁、清晰的自然语言文本，即观察。

Observation:从A到B的最短路线是......

这段Observation文本会被反馈给智能体，作为下一轮循环的主要输入信息，供其进行新一轮的Thought和Action。

agent应用的协作模式

作为开发者应用的agent

作为开发者应用的智能体可以理解为：把大语言模型接入代码、工具链和工程环境后形成的“开发协作者”。它不只是回答编程问题，而是能围绕一个开发目标去读代码、改代码、运行命令、看报错、写测试、提交变更。

目前市面上主流的 AI 编程辅助工具有：Claude Code，OpenAI codex，Cursor等等。

作为自主协作者的agent

与作为工具辅助人类不同，第二种交互模式将agent的自动化程度提升到了一个全新的层次，自主协作者。在这种模式下，我们不再是手把手地指导 AI 完成每一步，而是将一个高层级的目标委托给它。agent会像一个真正的项目成员一样，独立地进行规划、推理、执行和反思，直到最终交付成果。这种从助手到协作者的转变，使得 LLM agent更深的进入了大众的视野。它标志着我们与 AI 的关系从“命令-执行”演变为“目标-委托”。agent不再是被动的工具，而是主动的目标追求者。

当前，实现这种自主协作的思路百花齐放，涌现了大量优秀的框架和产品，从早期的 BabyAGI、AutoGPT，到如今更为成熟的 CrewAI、AutoGen、MetaGPT、LangGraph 等优秀框架，共同推动着这一领域的高速发展。虽然具体实现千差万别，但它们的架构范式大致可以归纳为几个主流方向：

  1. 单智能体自主循环：这是早期的典型范式，如 AgentGPT 所代表的模式。其核心是一个agent通过“思考-规划-执行-反思”的闭环，不断进行自我提示和迭代，以完成一个开放式的高层级目标。

  2. 多智能体协作：这是当前最主流的探索方向，旨在通过模拟人类团队的协作模式来解决复杂问题。它又可细分为不同模式： 角色扮演式对话：如 CAMEL 框架，通过为两个agent（例如，“程序员”和“产品经理”）设定明确的角色和沟通协议，让它们在一个结构化的对话中协同完成任务。 组织化工作流：如 MetaGPT 和 CrewAI，它们模拟一个分工明确的“虚拟团队”（如软件公司或咨询小组）。每个agent都有预设的职责和工作流程（SOP），通过层级化或顺序化的方式协作，产出高质量的复杂成果（如完整的代码库或研究报告）。AutoGen 和 AgentScope 则提供了更灵活的对话模式，允许开发者自定义agent间的复杂交互网络。

  3. 高级控制流架构：诸如 LangGraph 等框架，则更侧重于为agent提供更强大的底层工程基础。它将agent的执行过程建模为状态图（State Graph），从而能更灵活、更可靠地实现循环、分支、回溯以及人工介入等复杂流程。
    这些不同的架构范式，共同推动着自主agent从理论构想走向更广泛的实际应用，使其有能力应对日益复杂的真实世界任务。在我们的后续章节中，也会感受不同类型框架之间的差异和优势。

workflow和agent的差异

简单来说，workflow 是让 AI 按部就班地执行指令，而 agent 则是赋予 AI 自由度去自主达成目标。
